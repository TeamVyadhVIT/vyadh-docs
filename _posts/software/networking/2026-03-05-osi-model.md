## What is the OSI Model?

The **OSI (Open Systems Interconnection) Model** is a conceptual framework used to understand how data travels from one device to another over a network.

It divides network communication into **7 distinct layers**, each with a specific responsibility. This makes troubleshooting, design, and protocol development more structured and standardized.

---

## The 7 Layers at a Glance

| Layer No. | Layer Name | Function | Examples |
|-----------|-----------|---------|---------|
| 7 | **Application** | User interaction | HTTP, MQTT, FTP, DNS |
| 6 | **Presentation** | Data formatting & encryption | SSL/TLS, JPEG, MP4 |
| 5 | **Session** | Connection management | APIs, WebSockets |
| 4 | **Transport** | Reliable delivery | TCP, UDP |
| 3 | **Network** | Logical addressing & routing | IP (IPv4 / IPv6) |
| 2 | **Data Link** | MAC addressing, framing | Ethernet, WiFi |
| 1 | **Physical** | Hardware transmission | Cables, Antennas, Radio |

---

## Layer 7 — Application Layer

- **Closest layer to the end user**
- Provides the interface between the application and the network
- Does **not** refer to the application software itself, but the protocols that interact with it

**Handles:**
- Data requests and responses
- Network services for applications
- Communication interface

**Protocols:**
- `HTTP` / `HTTPS` — Web communication
- `MQTT` — Lightweight messaging for IoT/telemetry
- `FTP` — File transfer
- `DNS` — Domain name resolution
- `SMTP` — Email sending

**Rover context:**  
When the GCS receives telemetry data via MQTT, it operates at this layer.

---

## Layer 6 — Presentation Layer

- Acts as the **translator** between the application and the network
- Ensures that data sent from one system can be read by another

**Handles:**
- Data encryption and decryption
- Data compression
- Data format conversion (encoding)

**Examples:**
- SSL/TLS encryption before HTTPS transmission
- Video/image compression (JPEG, H.264) before streaming
- Character encoding (UTF-8, ASCII)

**Rover context:**  
SSL/TLS encryption of control commands operates at this layer.

---

## Layer 5 — Session Layer

- Manages the **lifecycle of a communication session**
- Establishes, maintains, and terminates connections between applications

**Handles:**
- Opening a session (connection initiation)
- Maintaining the session (keep-alive)
- Terminating the session (graceful close)
- Session recovery after interruptions

**Examples:**
- Opening an MQTT broker connection
- Maintaining a WebSocket connection
- Remote Procedure Call (RPC) sessions

**Rover context:**  
Keeping the rover ↔ GCS communication link alive uses session management at this layer.

---

## Layer 4 — Transport Layer

- Responsible for **end-to-end data delivery** between hosts
- Determines **how** data is transmitted — reliably or quickly

**Handles:**
- Segmentation of data into packets
- Reliable delivery (TCP) or fast delivery (UDP)
- Error detection and correction
- Packet sequencing and reassembly
- Flow control and congestion control

**Protocols:**

| Protocol | Description |
|---------|-------------|
| **TCP** | Connection-oriented, reliable, ordered delivery |
| **UDP** | Connectionless, fast, no guaranteed delivery |

**Rover context:**
- MQTT telemetry uses **TCP** for guaranteed delivery
- Live video streaming uses **UDP** for low latency

---

## Layer 3 — Network Layer

- Responsible for **logical addressing and routing** of data across networks
- Determines the best path for data to travel from source to destination

**Handles:**
- Assigning and interpreting IP addresses
- Routing packets between different networks
- Fragmentation of packets

**Protocols:**
- `IPv4` / `IPv6` — Logical addressing
- `ICMP` — Network diagnostics (ping, traceroute)
- `ARP` — Resolves IP addresses to MAC addresses

**Devices at this layer:**
- Routers

**Rover context:**  
IP routing determines which path rover telemetry takes to reach the remote GCS.

---

## Layer 2 — Data Link Layer

- Responsible for **reliable data transfer within the same local network (LAN)**
- Works with **MAC addresses** instead of IP addresses

**Handles:**
- Framing of data packets
- MAC (Media Access Control) addressing
- Error detection within a single link (CRC)
- Access to the physical medium (CSMA/CD for Ethernet)

**Sub-layers:**
- **LLC (Logical Link Control)** — Error checking, flow control
- **MAC (Media Access Control)** — Addressing, frame access

**Protocols:**
- `Ethernet` — Wired LAN
- `Wi-Fi (802.11)` — Wireless LAN

**Devices at this layer:**
- Switches, Network Interface Cards (NIC)

**Rover context:**  
Ensures telemetry data reaches the correct device within the rover's internal LAN using MAC addresses.

---

## Layer 1 — Physical Layer

- The **lowest layer** — deals with the actual physical transmission of raw bits
- Defines the electrical, optical, and radio specifications of the network

**Handles:**
- Transmission of raw binary data (0s and 1s)
- Physical connectors and cables
- Signal types: electrical, optical, radio

**Includes:**
- Ethernet cables (Cat5e, Cat6)
- Fiber optic cables
- Antennas and radio signals
- Voltage levels and signal timing
- Wi-Fi radio frequencies (2.4 GHz, 5 GHz)

**Devices at this layer:**
- Network cables, Hubs, Repeaters, Antennas

**Rover context:**  
The Wi-Fi antenna on the rover physically transmits data as radio signals at this layer.

---

## Data Flow Through the OSI Layers

When data is sent from one device to another, it travels **down** the OSI stack on the sender side and **up** on the receiver side:

```
Sender                          Receiver
───────                         ────────
[7] Application   ─── data ──►  [7] Application
[6] Presentation  ─ encrypt ──► [6] Presentation
[5] Session       ─ session ──► [5] Session
[4] Transport     ─ segment ──► [4] Transport
[3] Network       ─ packet ───► [3] Network
[2] Data Link     ─ frame ────► [2] Data Link
[1] Physical      ─ bits ─────► [1] Physical
```

Each layer **adds a header** (encapsulation) when sending and **removes the header** (decapsulation) when receiving.

---

## OSI vs TCP/IP Model

In practice, the **TCP/IP model** (4 layers) is more commonly used in real networks:

| TCP/IP Layer | OSI Equivalent |
|-------------|----------------|
| Application | Layers 7, 6, 5 |
| Transport | Layer 4 |
| Internet | Layer 3 |
| Network Access | Layers 2, 1 |

The OSI model is used primarily as a **teaching and troubleshooting framework**.
